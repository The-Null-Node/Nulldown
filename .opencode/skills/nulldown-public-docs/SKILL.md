# Nulldown Public Documentation

Write for developers, not internal operators. Establish what Nulldown is, why
it matters, what it enables, and only then how it works. MCP is the primary
agent workflow; CLI belongs in its own reference or an explicitly CLI-only
handoff.

Internal plans, authorization checks, test transcripts, session provenance,
root/branch/snapshot bookkeeping, smoke-test assertions, and completion rituals
are evidence, not source prose. Build a private fact sheet, write a sanitized
draft, then use `docs-audit` only to verify factual claims.

Do not make one research/review recipe the product definition. Do not publish a
first draft. Render and review the copy before separately authorized hosted
publication.
